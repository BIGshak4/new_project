מנוי Netlify Personal בעלות $9 לחודש **עדיין לא בוטל**. גם שרת Render במסלול Free נשמר. הם נשארים זמינים בתקופת המעבר; אין להסיק שהחיוב הישן הסתיים רק משום שהדומיין החדש פועל.

## כניסה לחשבון ואימות העבודה

ב־Supabase אומתו במסך הניהול ההגדרות הבאות:

```text
Site URL: https://muxijobrun.com

Redirect URLs:
https://jobrun-practice.netlify.app
https://jobrun-tasks.netlify.app
http://localhost:3000
http://localhost:3001
https://muxijobrun.com
https://www.muxijobrun.com
```

קובץ המקור של ההגדרות הוא `scripts/auth-config/supabase/config.toml`. יש לשמור בו את הכתובת הראשית החדשה ואת הרשימה המאושרת, כדי שעדכון הגדרות עתידי לא יחזיר את הכתובת הישנה. שינוי בקובץ לבדו אינו משנה את הפרויקט המתארח.

הכניסה היא באמצעות המייל והסיסמה של חשבון הפיילוט הקיים ב־<https://muxijobrun.com/#signin>. התחברות שנשמרה בדומיין Netlify אינה עוברת אוטומטית לדומיין החדש. פרטי החשבון וההרשאות נשארים באותו פרויקט Supabase; אין צורך ליצור חשבון חדש.

היישום מחזיר אישורי הרשמה לכתובת הראשית של הדפדפן. אין בו נתיב `/auth/callback` או `/auth/confirm`, וגם אין מסך איפוס סיסמה. הוספת כתובות לרשימת ההפניות אינה יוצרת מסך כזה. יש לשמר את תבניות האימות העובדות, ולהימנע מהפניית מייל לנתיב שאינו קיים.

בדיקת משתמש עם החשבון הקיים בוצעה בדומיין החדש:

1. הכניסה הצליחה, הפרופיל והיעד האישיים הקיימים הופיעו ונטענו 335 שאלות. ההתחברות נשמרה לאחר רענון.
2. נשמרה סימנייה לשאלה אחת. לאחר רענון וחזרה למאגר היא נשארה שמורה. לאחר מכן הוסרה הסימנייה ואומת שמספר הסימניות חזר לאפס.
3. נפתח תרגול בדיקה חדש אחד בשאלת זוג אינדקסים לסכום. הרצת Python עברה 6 מתוך 6 בדיקות בכ־4,057 מילישניות. לא הוגשה תשובה לדירוג AI. העורך נוקה ובסיום חזר המשתמש לדף הבית. תרגול הבדיקה נשאר ברשומות החשבון וצורך תרגול אחד מהמכסה היומית.

בקשות הבדיקה נצפו גם בלוגי ה־API החדש בשרת DigitalOcean, כך שאומת שהאתר השתמש בו בפועל במהלך הבדיקה.

לא נשלח מייל אישור יזום במסגרת הבדיקה, ולכן קבלת מייל וקישור האישור לא נבדקו בפועל. גם דירוג תשובה באמצעות מודל AI לא הורץ; מפתחות המודלים הקיימים לא שונו במעבר.

טיוטות שנשמרו רק בדפדפן הישן אינן עוברות בין הדומיינים. שמירה מפורשת לחשבון, כשזמינה, נפרדת מטיוטה מקומית.

## גישת מפעיל ובדיקות שוטפות

SSH מוגדר למשתמש `jobrun` באמצעות מפתח. כניסת root ב־SSH ואימות באמצעות סיסמה כבויים. UFW מגביל את פורט 22 לכתובת המקור שהוגדרה למפעיל. אם כתובת האינטרנט של המפעיל משתנה, יש לעדכן את הרשאת המקור דרך גישת ניהול מאושרת. פורטי היישומים 3000 ו־8000 פנימיים ל־Docker ואינם מפורסמים לאינטרנט.

כניסה מ־PowerShell במחשב המפעיל:

```powershell
ssh -i "$HOME/.ssh/jobrun_digitalocean_ed25519" jobrun@157.230.116.191
```

מיקום ה־Compose של **הפריסה הראשונית**:

```text
/opt/jobrun/releases/c3a2d28a9d9c964325a442d5b642354b862fcec2/deploy/selfhost
```

כעת אין קישור `current`. לאחר אימות מסלול הפרסום האוטומטי יש לתעד את מיקום הפריסה והפקודות המעודכנים לפני שימוש בהם. מתוך התיקייה שלעיל ניתן לבדוק את מצב השירותים בלי להציג הגדרות סודיות:

```sh
sudo docker compose -f compose.yaml ps
sudo docker stats --no-stream
```

השירותים מוגדרים `restart: unless-stopped`. בדיקת health שנכשלת דורשת בירור; עצם סימון המכולה כ־unhealthy אינו מפעיל אתחול אוטומטי.

ממחשב עם Node 24, מתוך שורש המאגר, אפשר לבדוק את הגרסה הציבורית:

```sh
node deploy/selfhost/verify-release.mjs c3a2d28a9d9c964325a442d5b642354b862fcec2 https://muxijobrun.com https://api.muxijobrun.com
```

הבדיקה דורשת תשובה תקינה וגרסה תואמת משני השירותים. היא אינה מבצעת כניסה לחשבון או בדיקת מודל AI.

## סודות וגיבויים

קובץ ההגדרות הפרטי של ה־API נמצא בשרת ב־`/opt/jobrun/shared/backend.env`. העתקי ההגדרות והייצוא המקורי מ־Render נשמרו במחשב המפעיל בתיקייה `C:/Users/harel/.jobrun-migration/`, המוגנת בהרשאות למשתמש ול־SYSTEM. קובץ ה־API המקומי נקרא `backend-selfhost.env`. המפתח הפרטי לשרת נמצא ב־`C:/Users/harel/.ssh/jobrun_digitalocean_ed25519`.

אלה מיקומים בלבד. אין להעתיק תוכן של הקבצים למאגר, לצ׳אט, ללוגי CI, לארגומנטי build או לתמונות Docker. משתני `NEXT_PUBLIC_*` מכילים רק תצורת לקוח ציבורית ומוטמעים בבניית האתר.

הגיבוי השבועי הוגדר ליום רביעי בחלון **04:00–08:00 UTC**. עד שיופיע גיבוי ראשון ותבוצע בדיקת שחזור, שחזור מלא של השרת עדיין אינו מאומת. גיבוי השרת אינו מחליף את מדיניות הגיבוי של מסד הנתונים והאחסון ב־Supabase.

יש לשמור גם את קובצי התצורה ואת נתוני התעודות של Caddy מחוץ לשרת, לעדכן את מערכת ההפעלה והתמונות, ולנטר שטח דיסק וזמינות. כרגע לא הוגדרה התראת זמינות חיצונית. שרת יחיד מארח את האתר ואת ה־API, ולכן תקלה בו יכולה להשפיע על שניהם.

## העדכון הבא וחזרה לגרסה קודמת

מסלול הפרסום האוטומטי מפותח בנפרד. עד שתועדה הפעלתו ונבדקה פריסה של commit חדש, בדיקת workflow ירוקה או `git push` לבדם אינם ראיה שהאתר החי עודכן.

כל פרסום צריך לשמור על אותו SHA מלא לאתר ול־API, בניית תמונות מחוץ לשרת הקטן, בדיקות לפני החלפה ובדיקת גרסה לאחריה. שינוי כתובת API או תצורת Supabase ציבורית דורש בנייה מחדש של האתר. אין לבצע build כבד על שרת ה־production בגודל 2GB.

יש לשמור תמונות ותצורה של גרסה תקינה קודמת לצורך חזרה מתואמת של האתר וה־API יחד. חזרה של קוד אינה כוללת שחזור מסד נתונים או זריעה מחדש. פקודות הפריסה הידניות והבדיקות מפורטות ב־[README.md](README.md); יש להשתמש במסלול העדכון הסופי רק לאחר שאומת ותועד.

ביטול Netlify או הסרת Render יגיעו לאחר בדיקת המשתמש, אימות עדכון אוטומטי ובדיקת אפשרות החזרה. לוח המשימות עדיין תלוי בפריסה הישנה ולכן נשאר זמין שם.
