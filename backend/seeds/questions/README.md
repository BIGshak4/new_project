# Question bank

The bank is Harel's 30 example questions, enriched with what the engine needs to
evaluate an answer. Three files matter:

| File | What it is | Who edits it |
|---|---|---|
| `../../../example_question/questions.json` | The question text: prompts, references, one hint, both languages | Harel (content) |
| `enrichment/hardware.json`, `enrichment/software.json` | Skills, rubric, hint levels 1–3, common errors, accepted approaches, deterministic checks | Content authors and reviewers |
| `example_bank.json` | The merge of the two, read by the seed loader | Nobody: generated by `scripts/build_example_bank.py` |

After editing either input:

```powershell
uv run python scripts/build_example_bank.py     # regenerate example_bank.json
uv run python scripts/seed_db.py --check         # validate everything together
uv run python scripts/seed_db.py                 # load into Supabase (needs DATABASE_URL)
```

The loader upserts by key, so Harel's existing rows are enriched in place. His app
keeps working: it reads the prompt, the hints and the reference, and `assets`
keeps every field it and his access policy rely on.

## What a reviewer checks before a question is published

A question is served to real candidates only when `status` is `published`,
`reuse_status` is `permitted` and `reviewed_by` is set, and a language is served only
when its `parity_checked` is true. Nothing here is published yet. For each question:

1. **Technical correctness.** Is the reference solution right, including every number in a trace?
2. **Rubric.** Do the criteria cover what a complete answer must contain, and do the
   weights reflect what matters? Weights must sum to 1.0.
3. **Hints.** Level 1 offers an angle and reveals nothing. Level 2 names the concept.
   Level 3 gives the first concrete step. A level-3 hint caps the level a candidate can
   show on that skill, so it must not give the whole answer either.
4. **Common errors.** Each key names a real mistake candidates make. `core: true` means a
   candidate who makes it does not understand the central idea; that bands the answer
   WEAK and caps the level at 2, so use it sparingly.
5. **Deterministic check.** If present, is the spec right? The loader runs each check's
   `check_self_test` (known-good and known-bad answers) and refuses the file if any fails.
6. **Hebrew/English parity.** Same requirements, same difficulty, same rubric meaning.
   When satisfied, set `parity_checked: true` and `parity_checked_by` in the translation.
7. **Provenance.** `source_name`, `source_url`, `license` and `reuse_status` are filled in
   and true. Company attributions are never invented.

Then set `status: "published"`, `reviewed_by` and `reviewed_at`.

## Exposure risk

`exposure_risk` lowers the evidence weight of widely known questions (`high` = 0.6,
`medium` = 0.85). The majority vote, popcount, power-of-two, merge, brackets and
list-reversal questions are marked `high` because they appear in every interview
preparation resource.
