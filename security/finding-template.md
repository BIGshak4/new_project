# SEC-YYYY-NNN — Short descriptive title

- **Severity:** Critical / High / Medium / Low / Informational; explain the impact and prerequisites.
- **Status:** Confirmed / open, fixed locally, mitigated, deployed / verified, or operator action required.
- **Discovered:** YYYY-MM-DD
- **Review:** link to the relevant run report.
- **Affected revision and components:** exact scope, not an assumed deployment.

## Problem and impact

Explain the boundary that failed, who could exploit it, and the resulting confidentiality, integrity, availability, or cost impact. Separate observed behavior from theoretical consequences.

## Safe reproduction

Describe a local or isolated test using synthetic data. Do not include secrets, live object locators, real account identifiers, or a production attack recipe.

## Exact remediation

List changed files and the behavior introduced. Explain compatibility, migrations, and any feature that is deliberately disabled.

## Verification

Record failing-before evidence, passing-after tests, relevant regression suites, and deployment/database checks. Record skips and unavailable checks explicitly.

## Remaining work

State residual risks, operator actions, retest triggers, and any limitations of the mitigation. Do not mark the record closed merely because a commit exists.

## References

Link primary technical documentation or advisories supporting the finding.
