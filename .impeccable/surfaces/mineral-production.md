# Production Mineral promotion

Approved by the founders on 2026-10-29 after choosing candidate Mineral in
`/color-preview`, then approving the implementation plan. Existing Ion
composition, typography, imagery, content and functional behavior are binding.
This is a precisely specified palette promotion, not an open visual-world
exercise; no new concept tournament or generated mock is required.

## Direction contract

THESIS: Promote the approved cool mineral gray-green grounds and plum type into
the real practice site's semantic color system, with a quiet technical grid at
the landing demonstration and clean working sheets everywhere else.

OWN-WORLD: Use Mineral's exact ten palette values. Retain Heebo, JetBrains Mono,
the authored purple chip, the live XOR interaction and existing Ion geometry.
Retain the existing dark Ion theme, all semantic status colors and saved theme
preferences. First visits remain light.

STORY: A visitor recognizes the technical practice product, enters their real
account, and uses the existing bank, learning tools, feedback, progress, tour
and support. Palette promotion never replaces production with sample data.

FIRST VIEWPORT: The real landing copy and actions remain beside the real chip
and XOR controls. Mineral's fine 40px grid sits behind this region; a flat framed
green-gray panel holds the chip. Header and working surfaces use the lighter
Mineral surface, with purple text and primary actions.

FORM: Persuade on the landing, Operate inside the product. A light-only token
override imported after ion.css updates shared consumers including portals.
Named landing selectors apply the approved region treatment. No backend,
question, payment, duel, account or admin/task-site change belongs here.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Verification and integration boundary

Check light/dark, Hebrew/English, desktop/mobile, the real landing, authentication,
library, practice tools, support/inbox portals and onboarding. Verify contrast,
overflow, theme persistence and existing application checks. New game screens
must use --paper, --surface, --surface-2, --ink, --muted, --line, --link, --action
and --action-ink. Only this task owns mineral.css and its root layout import.
Keep preview routes and the separate task/admin app unchanged. No new raster
asset is produced; the existing chip and its provenance remain unchanged.
