# Gray-green and purple colour exploration

Mode: Operate, serving a visual comparison of the existing practice product. This is a preview-only extension; it does not select or replace the production identity.

## Direction contract

THESIS: Make ten genuinely distinguishable gray/green background treatments comparable on the same familiar JobRun landing and question-library views, keeping purple as the brand anchor.

OWN-WORLD: Preserve the existing Hebrew-first Ion typography, chip asset and product vocabulary. Explore silver fog, sage, celadon, olive stone, mineral gray, subtle green paper, a gray/green split field, graphite, forest night and fern. Their grounds, elevation and purple contrast differ deliberately; this is not ten green tints on the same ground.

STORY: A founder chooses a named treatment, views both landing and library at useful scale, checks a phone-sized view or opens it full size, and shares the exact selection. Selection changes only the preview.

FIRST VIEWPORT: Compact neutral comparison controls expose all ten named swatches, current treatment, landing/library switches and full-size viewing. The selected site dominates the viewport. Opening a shared embedded URL shows only the selected site, with working local navigation and no fake authenticated account.

FORM: A precisely scoped palette comparison inside the established product world; no new identity is selected. Inherit its existing composition under new-work.md section 3: “Never run the script for a local extension or a precisely specified narrow request; shape those directly.” No generated or retrospective seed applies. The user's explicit ten-variant request fixes the number.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Scope and quality

Use the existing local SiteSimulation engine in an isolated route, never the production application component. Its sample content is labelled as a demonstration. Keep the main site, saved theme preference, real users, questions and backend workflows untouched. Existing root providers may remain inherited; do not add a new backend integration. New preview styles must be scoped, keyboard-operable and responsive, with readable contrast across body, muted copy and actions. Respect reduced motion; palette swaps are immediate. Keep the unchanged existing asset provenance. Document only the preview scope; do not promote candidate palettes into DESIGN.md before the user's choice.
