# Updates and support

Mode: Operate. This is a local extension of the existing Ion practice application, with private founder controls in the existing task/admin workspace.

## Direction contract

THESIS: Give a learner a clear answer to “what changed, and what happened to my report?” without interrupting an active solution.

OWN-WORLD: Preserve Ion's cream/purple light theme, violet dark theme, Heebo type, labelled controls and sage/green founder workspace. Reuse semantic tokens and existing navigation density.

STORY: The top-bar “עדכונים ופניות” / “Updates & support” action shows unread state. A learner reads a general update or opens their own report to see its status, the team's public replies and an explicit resolution. Founders compose drafts and intentionally publish announcements, and distinguish public replies from internal notes.

FIRST VIEWPORT: A labelled bell action belongs with the top-bar controls. Opening the inbox protects the active practice task and offers updates and personal reports with written states, dates, read indicators and a clear return. Report details keep the original description beside public treatment history. Founder navigation gains a plain-language publishing section.

FORM: Inherit the incumbent composition. No ranked concept list or generated seed applies: reference/new-work.md section 3 instructs “Inherit its world and composition” and “Never run the script for a local extension or a precisely specified narrow request; shape those directly.”

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Behavior and boundaries

Read state is account-specific. A list refresh never silently marks content read; reading an item does. Anonymous visitors get a clear sign-in state. Public report history excludes internal notes, admin identities and audit records. Closing/resolving a report requires a meaningful public explanation. Publishing is explicit, preserves a saved draft on failure and never sends a test broadcast to real users. No email or push delivery is implied.

Follow both themes and languages, mobile-safe sizing, correct bidirectional content, keyboard focus/Escape, reduced motion, loading/empty/error states and retryable operations. Reuse nested body-scroll locking and keep inbox dialogs outside the tour's covered-page inert boundary.
